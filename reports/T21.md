## What is implemented

- `scripts/t21_prior_shift.py` (WORKORDER v2.3, T21; no API calls on the real data, the bank tables are cache hits of T07 and T14). The lr combiner over `q_direct` and the indicators is fitted on the source training split; its out-of-fold scores are calibrated on train (`--calibration platt` default, `isotonic`, `none`; T13's calibration step), which gives posteriors under the source prior pi_s = 0.5. The source operating threshold is the best-F1 threshold on the calibrated train scores; its false-positive rate on the source train benign pages is the target FPR used by the label-free threshold rule.
- `src/combine/prior_shift.py`: logit shift by `log(pi/(1-pi)) - log(pi_s/(1-pi_s))`; Saerens-Latinne-Decaestecker EM for the target prior from unlabelled calibrated scores (`em_prior`: re-weight the posteriors by the current prior ratio, re-estimate the prior as the mean re-weighted posterior, iterate to 1e-8); the label-free threshold for a target FPR from calibrated posteriors (`threshold_for_expected_fpr`: expected FPR(t) = sum_{p_i >= t}(1 - p_i) / sum_i (1 - p_i)); per-indicator isotonic maps fitted on the source train split and applied to the target before a refitted combiner (`PerIndicatorIsotonic`).
- Methods per target (rows of `results/t21_prior_shift.csv`): `R0` (frozen Putra threshold), `prior_known` (shift with the true target prior, threshold re-derived for the source FPR without labels), `prior_known_bayes` (same shift, Putra posterior threshold kept), `prior_em` and `prior_em_bayes` (the EM prior instead of the true one; `prevalence_estimated` filled), `R1` (threshold refitted on `--r1` = 200 labelled sites from `--adapt-dataset phreshphish-adapt`; without an adaptation set, a held-out slice of the target, development only). Table 17 columns come first (`method, prevalence_true, prevalence_estimated, threshold, f1, precision, recall, auroc, ece_before, ece_after`), then `target, score, n, n_pos, n_adapt, em_iterations, target_fpr, split_source`. `ece_before` is the ECE (10 equal-mass bins) of the calibrated combined score on the target, `ece_after` that of the combiner on the isotonic-mapped indicators.
- Targets are `dataset[:split][@variant]`, default `phreshphish-native,phreshphish-20k` (the benchmark test split at its native base rate and the balanced 20k sample); the per-site file `results/t21_<target>_scores.csv` (calibrated, shifted scores and every method's threshold) feeds `scripts/t_stats.py` (pair "prior_em vs R1"). The script prints, per target, the share of the R0-to-R1 F1 gain recovered without labels, the quantity H9 is decided by (threshold two thirds).
- Unit tests: `tests/test_v23_methods.py::test_em_prior_recovers_known_prior` (40,000 synthetic sites with Bayes-calibrated source posteriors; priors 0.1, 0.3, 0.8 recovered within 0.02 and the shifted posteriors average to the target prior), `test_expected_fpr_threshold_and_isotonic_transfer`.

## Bootstrap exercise (code path only)

```bash
python scripts/t21_prior_shift.py --dataset bootstrap-phreshphish --variant S1 \
    --targets bootstrap-phreshphish:test,bootstrap-putra:all@S2
```

- Source: 140 PhreshPhish bootstrap train sites. Targets: the 60 PhreshPhish bootstrap test sites and the 49 Putra bootstrap sites (S2 bank table, which contains the 15 S1 columns). 641 cached requests, no live call. Written: `results/t21_bootstrap-phreshphish_S1_prior_shift.csv` (12 rows: six methods x two targets, all columns filled, `prevalence_estimated` for the EM rows), `results/t21_bootstrap-phreshphish_scores.csv`, `results/t21_bootstrap-putra_scores.csv`.
- EM converged in 11 and 18 iterations. Both bootstrap targets are balanced, so the exercise shows the code path, not a prevalence shift; the native-rate target only exists once `phreshphish-native` is sampled. On samples of 49 to 60 sites the EM estimate deviates from the true prior, which is the expected behaviour when the source posteriors are not calibrated on the target; the unit test on calibrated synthetic scores recovers the prior.
- Bugs found and fixed: a target whose bank responses are not cached produced an empty table and a division by zero in the logit shift (now skipped with a message, and `prior_shift` guards pi in (0, 1)); the target variant can now differ from the source variant (`@variant`).
