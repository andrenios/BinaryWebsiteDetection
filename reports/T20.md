# T20: value-of-information and conformal evidence acquisition (script status, 2026-10-04)

Status: **implemented and exercised on the bootstrap samples with the pseudo split, cached responses only; not run on the real data.** No detection number in this report. Blockers are listed at the top of `reports/T21.md`. Spend in this session: 0 USD.

## What is implemented

- `scripts/t20_acquisition.py` (WORKORDER v2.3, T20). No new API calls on Putra: the stage probabilities are the cached `q_direct` responses on S0 and the cached bank responses on S1 and S2 (T06 / T07 experiment names; the content-addressed cache serves them under any experiment name). Per stage the score is `q_direct` (`--score direct`) or the lr combiner refitted on the training split with out-of-fold scores on train (`--score lr`, default), followed by a calibration map fitted on train (`--calibration platt` by default, `isotonic`, `none`; this is how T13's calibrated scores feed T20). Twin instantiation via `--instantiation twin-<model>` (T09 tables).
- `src/cascade/voi.py`: transition model (p_k binned into 20 equal-mass bins on train, empirical distribution of p_{k+1} per bin stored as a 20 x 20 table of cell probabilities with the mean next-level score per cell; `results/t20_<dataset>_voi_transition.csv`, long format, re-loadable), `decide(p) = min(c_FN p, c_FP (1 - p))`, the myopic rule "acquire iff a_{k+1} + E[decide(p_{k+1}) | p_k] < decide(p_k)", and the per-site run over an ordered list of levels (a level missing for a site is skipped; the last available level decides).
- Costs: c_FP = 1, c_FN in `voi_cost_ratios` (1, 10, 100); acquisition costs from the T11b unit-cost grid (GET 0.5 / 1.5 / 3 s, render 2 / 5 / 10 s, screenshot + OCR 0.3 / 1 / 2 s; S1 = render, S2 = render + OCR, S5 = GET) converted at the stated exchange rate `voi_seconds_per_fp_unit` (default 60 s per unit of c_FP; recorded in the output column `exchange_seconds_per_fp_unit` and to be quoted in the paper). F1 is computed at the train-fitted threshold of the stage at which each site stopped, as in T11b, so the rows are comparable with the swept band and with always-fetch; `expected_cost` is the acquisition cost paid plus the Bayes decision cost at the final probability.
- `results/t20_<dataset>_voi_test.csv`: Table 15 columns first (`cost_ratio, a_S1, a_S2, f1, auroc, stop_S0, stop_S1, stop_S2, fetched_fraction, expected_cost, split_source`), then `grid_point, get_s, render_s, ocr_s, central, usd_per_1000, score, calibration, exchange_seconds_per_fp_unit`; 27 grid points x 3 cost ratios plus the reference rows `always fetch S0 / S1 / S2` and the swept band(s) read from the T11b test table of the same arm. Per-site scores and stop levels at the central grid point go to `results/t20_<dataset>_voi_test_scores.csv` for `scripts/t_stats.py` (VoI against the swept band and against S1 alone).
- `src/cascade/conformal.py`: split-conformal thresholds per non-final level on the calibration half of a 50/50 stratified split of the training split (the other half fits the lr and the calibration map); nonconformity 1 - p_k on phishing pages for the lower stop and p_k on benign pages for the upper stop, finite-sample-corrected (1 - alpha) and (1 - beta) quantiles (`ceil((n+1)(1-alpha))`-th smallest; infinite when n is too small for alpha, which means "never stop at this level"). Evaluated on test and frozen on the transfer sample (`--transfer-dataset phreshphish-20k --transfer-stages S0,S1`). `results/t20_<dataset>_conformal_test.csv` and `results/t20_phreshphish_conformal_test.csv` carry the Table 16 columns `alpha, beta, level, threshold_low, threshold_high, fraction_stopped, realised_miss_rate, realised_fp_rate, n` first. `realised_miss_rate` is the share of all phishing pages declared benign at or before the level (cumulative; the marginal quantity the quantile bounds per level); `realised_fp_rate` the share of benign pages declared phishing at or before the level.
- Figures: `figures/t20_fetched_vs_costratio.*` (fetched fraction and F1 against the cost ratio at the central acquisition costs) and `figures/t20_conformal_miss_vs_alpha.*` (realised miss rate and fraction stopped at the first level against alpha).
- Unit tests: `tests/test_v23_methods.py::test_voi_rule_two_level_hand_computed` (an eight-site two-level transition model with hand-computed expected costs; the rule acquires exactly when a_{S1} is below the hand-computed break-even values 0.7 and 0.3), `test_equal_mass_edges_and_bins`, `test_conformal_quantile_and_coverage` (realised miss rate within +/- 0.01 of alpha for alpha 0.01 and 0.05 on 50,000 synthetic pages; upper stop within 0.04 to 0.06 for beta 0.05).

## Bootstrap exercise (code path only)

```bash
python scripts/t20_acquisition.py --dataset bootstrap-phreshphish --stages S0,S1 --score lr
python scripts/t20_acquisition.py --dataset bootstrap-putra --stages S0,S1,S2 --score direct \
    --transfer-dataset bootstrap-phreshphish --transfer-stages S0,S1 --transfer-split test
```

- Run 1 (lr arm, two levels): 140 train / 60 test sites, 400 cached requests. Written: `results/t20_bootstrap-phreshphish_{voi_test,voi_transition,voi_test_scores,conformal_test}.csv`, `results/t20_bootstrap-phreshphish_conformal_test_direct.csv` is the transfer file of run 2, figures `figures/t20_bootstrap-phreshphish_{fetched_vs_costratio,conformal_miss_vs_alpha}.*`. The swept-band reference row was read from `results/t11b_bootstrap-phreshphish_lr_S0-S1_test.csv`; the three cost ratios produced three different fetched fractions, i.e. the rule reacts to the loss asymmetry as intended.
- Run 2 (direct arm, three levels, transfer): 34 train / 16 test Putra bootstrap sites plus 60 PhreshPhish bootstrap test sites, 269 cached requests. All stop fractions over three levels and the transfer evaluation were produced.
- Expected degenerate behaviour at this size: with 17 phishing pages in the calibration half, the finite-sample quantile at alpha = 0.01 and 0.05 is infinite, so the conformal thresholds are -inf / +inf and nothing stops before the last level. On Putra (about 1,540 phishing pages in the calibration half) the thresholds are finite. The transition model collapsed some bins because the API returns two-decimal probabilities (ties); the equal-mass binning drops duplicate cut points and keeps a cut at the maximum, which the unit test covers.
- One bug found and fixed: the equal-mass binning lost the split between the top tied value and the rest (unit test added).

## Open issues

- Acquisition seconds remain placeholders on Putra (decisions D14); the VoI table is therefore reported in pages fetched per stage and in cost units, never in seconds.
