## What is implemented

- `scripts/t19_stability.py` (WORKORDER v2.3, Section 6, Phase 4b). Inputs are decision tables obtained through `scripts/_bootstrap.py::decision_table`: for the decision model the bank is sent through the cached Jev client (content-addressed cache, so the Putra train and the T14 transfer tables are cache hits and only the PhreshPhish stability sample costs new requests); for the open-weight twin (`--instantiation twin-<model>`) the T09 tables are read instead and every output name carries the suffix `_twin-<model>`.
- `src/combine/stability.py`: per-indicator AUROC and sign on each corpus, the class rule (stable: same sign and oriented AUROC > 0.60 on both; artefact: oriented AUROC > 0.65 on one corpus and < 0.55 or reversed on the other; uninformative otherwise), the inventory table with the columns of `paper/tables.md` Table 13 (`question, auroc_putra_train, sign_putra, auroc_phresh_stab, sign_phresh, class, rank_putra, rank_phresh`), the stable-set extraction, and the semantic / deterministic partition constants used by T07.
- Stable-set freeze: on `--dataset putra --variant S1` with the decision model the stable set is written once to `src/questions/stable_set_v1.yaml` (`frozen: true`, rule, corpus sizes, per-question classes); later runs load the file and warn if a recomputation would differ. Every other dataset writes a development file under `results/` instead (`results/t19_<dataset>_<variant>_stable_set_dev.yaml`).
- Combiners fitted on the source training split only, thresholds from the out-of-fold scores: `lr all indicators` (14 indicators without `q_direct`), `lr stable set`, `q_direct` alone, and `lr all indicators + q_direct` (the T07 combiner, for comparability). Each is evaluated once on the source test split and frozen (R0) on the transfer sample(s) (`--transfer-dataset`, plus `--extra-transfer phishark=... fresh=...`). Table 14 columns `combiner, n_indicators, putra_test_f1, r0_f1_phreshphish, r0_f1_phishark, r0_f1_fresh, transfer_loss, ci_low, ci_high` come first; the CI of the transfer loss is a two-sample bootstrap over the source test sites and the transfer sites (1,000 resamples; `src/eval/metrics.py::two_sample_bootstrap_diff`), because the two F1 values live on different site sets. The paired comparison between the stable-set and the all-indicator combiner on the same transfer sites is produced by `scripts/t_stats.py` from the per-site file `results/t19_<tag>_transfer_scores.csv` that this script writes (scores and train-fitted thresholds per combiner).
- Figure: `figures/t19_stability_scatter.{pdf,png}` (AUROC on the source corpus against AUROC on the stability corpus, marker by class; `src/eval/plots.py::stability_scatter`).
- T07's part of the task (`results/t19_semantic_set.csv`, forward selection restricted to the semantic indicators, train out-of-fold scores) is in `scripts/t07_bank.py` and was exercised on both bootstrap samples.

## Bootstrap exercise (code path only)

Command (zero-spend config, `MAX_USD: 0`):

```bash
python scripts/t19_stability.py --dataset bootstrap-putra --variant S2 \
    --stability-dataset bootstrap-phreshphish --stability-split train \
    --transfer-dataset bootstrap-phreshphish --transfer-split test
```

- Source: 33 train / 16 test Putra bootstrap sites (S2 bank, 17 questions; the 15 S1 questions are the common set used across corpora). Stability sample: 140 PhreshPhish bootstrap train sites. Transfer: 60 PhreshPhish bootstrap test sites. All 747 requests were served from the cache.
- Written: `results/t19_bootstrap-putra_S2_stability_indicators.csv` (14 indicator rows, all Table 13 columns with the dataset-specific names `auroc_bootstrap_putra_train`, `sign_bootstrap_putra`, `auroc_bootstrap_phreshphish_stab`, `sign_bootstrap_phreshphish`, `class`, `rank_bootstrap_putra`, `rank_bootstrap_phreshphish`), `results/t19_bootstrap-putra_S2_transfer_by_combiner.csv` (four combiner rows, `r0_f1_phreshphish` filled, phishark and fresh empty), `results/t19_bootstrap-putra_S2_transfer_scores.csv`, `results/t19_bootstrap-putra_S2_stable_set_dev.yaml`, `figures/t19_bootstrap-putra_S2_stability_scatter.*`.
- All three classes occurred on the bootstrap samples, so every branch of the class rule and of the stable-set combiner was executed; the per-indicator inventory, the figure and the transfer table are development artefacts and are not to be read as findings (`split_source = pseudo`, bootstrap data).
- Two bugs were found and fixed during the exercise: the class rule read its inputs by position from the inventory tuple (wrong columns once the sign column names changed) and collided column names when the source and stability corpora share a prefix; both are covered by `tests/test_v23_methods.py::test_stability_classification`.
